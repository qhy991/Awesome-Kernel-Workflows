# ArchAgent: 进化式缓存替换策略优化

**论文**: [ArchAgent: Evolutionary cache replacement policy optimization](https://arxiv.org/abs/2602.22425)  
**发表**: arXiv preprint (2024)

## 概述

ArchAgent 实现了 **AlphaEvolve: 带短-长评估级联的进化搜索**，用于 LLC（末级缓存）替换策略优化。工作流使用 ChampSim 周期精确模拟，通过基于种群的搜索和基于适应度的选择来进化 C++ 缓存替换策略。

## 核心洞察

**短 → 长评估级联**：在长跟踪（1 亿条指令）上评估策略成本高昂。ArchAgent 首先用快速短评估（1000 万条指令）过滤种群，然后仅对幸存者运行彻底的长评估。这节省 10 倍计算量，同时保持搜索质量。进化搜索通过变异（算法变更、参数调优）和交叉（组合父代元素）系统地探索策略空间。

## 循环拓扑

```
基于种群的进化搜索：

种子种群（SEED POPULATION）:
  从已知策略采样（LRU, RRIP, SHiP, Hawkeye）
  LLM 生成的新颖策略
  混合：组合多个策略的元素
  → 初始种群（N=20-50）

代际循环（GENERATION LOOP，10-30 代）:

  短评估（SHORT EVALUATION）:
    在 1000 万条指令跟踪上评估所有候选
    → 快速适应度筛选

  选择（SELECTION）:
    选择 top-K 候选（锦标赛或 top-K）
    → 长评估的幸存者

  长评估（LONG EVALUATION）:
    在 1 亿条指令跟踪上评估幸存者
    → 准确适应度

  进化（EVOLUTION）:
    选择父代（适应度比例或锦标赛）
    变异：算法变更、参数调优、模式注入
    交叉：组合两个父代的元素
    多样性检查：拒绝重复
    → 下一代

  收敛检查（CONVERGENCE CHECK）:
    如果 N 代无 IPC 改进 → 停止
    如果达到最大代数 → 停止
    如果种群多样性 < 阈值 → 停止

报告（REPORT）:
  最佳策略 + 进化轨迹
```

## 组件

### 种子种群策略

1. **从已知策略采样**: LRU, RRIP, SHiP, Hawkeye
2. **LLM 生成的新颖策略**: 创造性策略设计
3. **混合**: 组合一个策略的预测逻辑与另一个策略的更新逻辑

### 短评估（1000 万条指令）

- **目的**: 快速适应度筛选以过滤种群
- **加速**: 比长评估快约 10 倍
- **指标**: IPC（每周期指令数）、MPKI（每千条指令缺失数）

### 长评估（1 亿条指令）

- **目的**: 最终排名的准确适应度
- **指标**: IPC、MPKI、相对基线的加速比（LRU 或 RRIP）

### 进化算子

1. **变异**:
   - **算法层**: 更改预测逻辑、更新机制
   - **参数层**: 调整阈值、计数器、表大小
   - **模式层**: 注入已知的良好模式（如旁路启发式、重用距离估计）

2. **交叉**:
   - 组合父代 A 的预测逻辑与父代 B 的更新逻辑
   - 合并两个父代的参数集

3. **多样性维护**:
   - 拒绝重复或近似重复（代码相似度 > 阈值）
   - 通过距离度量维护种群多样性（编辑距离、AST 相似度）

### 选择策略

- **Top-K**: 选择 K 个最佳候选
- **锦标赛**: 随机配对，胜者晋级
- **适应度比例**: 概率与适应度成比例

## 硬件目标

- **CPU 缓存层次结构（LLC 重点）**
- **架构**: x86-64（Intel、AMD）、ARM（可选）
- **缓存级别**: LLC（末级缓存）- 主要目标；L1/L2 - 未来扩展

## 反馈信号

- **ipc**（越高越好）：每周期指令数（主要适应度）
- **mpki**（越低越好）：每千条指令缺失数（次要）
- **speedup**（越高越好）：相对基线的加速比（LRU 或 RRIP）

## 典型结果

- **IPC 改进**: 1.05x - 1.20x（相对 LRU 基线）
- **代数**: 10-30
- **种群大小**: 20-50
- **运行时间**: 2-8 小时（取决于跟踪长度、种群大小）

## 使用示例

```javascript
// 在 Claude Code 中：
/workflow archagent-cache-policy-optimization

// 工作流将：
// 1. 初始化 ChampSim 环境
// 2. 创建种子种群（LLM + 已知策略）
// 3. 对于每一代：
//    a. 短评估（1000 万条指令）→ 过滤种群
//    b. 长评估（1 亿条指令）→ 准确适应度
//    c. 选择 → 顶级表现者
//    d. 进化 → 变异 + 交叉 → 下一代
// 4. 返回最佳策略及分析
```

## 关键参数

- **population_size**: 每代候选数量（默认: 30）
- **max_generations**: 最大代数（默认: 20）
- **short_trace_length**: 短评估跟踪长度（默认: 1000 万条指令）
- **long_trace_length**: 长评估跟踪长度（默认: 1 亿条指令）
- **selection_top_k**: 长评估的幸存者数量（默认: 10）
- **mutation_rate**: 变异概率（默认: 0.3）
- **crossover_rate**: 交叉概率（默认: 0.5）
- **diversity_threshold**: 重复拒绝的最小代码相似度（默认: 0.9）

## 注意事项

- **短 → 长级联**: 通过早期过滤不良候选节省计算
- **AlphaEvolve**: 基于种群，而非单轨迹
- **ChampSim 集成**: 周期精确的缓存行为模拟
- **多样性维护**: 防止过早收敛到局部最优
- **C++ 代码生成**: 策略是可执行的 ChampSim 模块
- **评估成本**: 长跟踪每个策略可能需要数分钟
- **跟踪**: SPEC CPU 2017、内存密集型工作负载
