# GPU Forecasters: 带学习加速预测的选择性代理优化

**论文**: [GPU Forecasters: Selective surrogate optimization with learned speedup forecasting](https://arxiv.org/abs/2605.31464)  
**发表**: arXiv preprint (2024)

## 概述

GPU Forecasters 实现了 **带学习加速预测器和原生弃权机制的 PUCT 搜索**。工作流训练语言模型以 8 个序数区间预测内核加速比，然后使用 PUCT 树搜索探索优化空间。预测器可以在不确定时弃权，推迟到实际 GPU 执行。这在固定 GPU 预算下平衡探索（高不确定性）和利用（高预测加速比）。

## 核心洞察

**带弃权机制的选择性代理**：训练代理模型预测加速比可以节省 GPU 评估，但代理误差可能误导搜索。GPU Forecasters 的关键创新是**原生弃权机制**：预测器在不确定时推迟到 GPU 执行。PUCT 搜索利用这一点：探索高不确定性区域（弃权 → GPU 评估），利用高置信度高加速比区域（预测 → 无 GPU 成本）。这实现了比纯代理或纯搜索更好的 GPU 预算效率。

## 循环拓扑

```
两阶段工作流：训练预测器 → PUCT 搜索

阶段 1: 训练预测器（课程阶段）
  生成初始内核候选（N=50-100）
  在 GPU 上执行（真实加速比）
  训练预测器：内核代码 + 上下文 → 8 区间序数分类
  验证预测器：准确率、弃权率
  → 训练好的预测器模型

阶段 2: PUCT 搜索（固定 GPU 预算）
  初始化搜索树（根 = 基线内核）
  
  对于每个搜索步骤（直到 GPU 预算 M 耗尽）：
    1. 选择（SELECT）: 选择 PUCT 分数最高的节点
       PUCT(node) = Q(node) + C * sqrt(log(N_parent) / N_node)
    
    2. 生成（GENERATE）: 创建子候选（变异、变体）
    
    3. 预测（FORECAST）: LM 预测加速比区间或弃权
       - 如果弃权或高不确定性：在 GPU 上执行（使用预算）
       - 如果预测：使用预测加速比（无 GPU 成本）
    
    4. 更新（UPDATE）: 更新树统计（Q 值、访问计数）
  
  → 带最佳内核路径的搜索树

评估（EVALUATE）:
  在 GPU 上评估搜索树的 top-K 候选
  → 最佳内核 + 搜索轨迹

报告（REPORT）:
  最佳内核 + 预测器分析 + GPU 预算使用
```

## 组件

### 加速比预测器

**架构**: Transformer LM（如 CodeLlama、基于 GPT）

**输入**:
- 内核代码（CUDA 源码）
- 上下文（操作名、张量形状、数据类型）

**输出**:
- 8 区间序数分类: [0.5x, 0.7x, 0.9x, 1.0x, 1.2x, 1.5x, 2.0x, 3.0x+]
- 弃权选项：不确定时推迟到 GPU

**训练**:
- 在（内核，实际加速比）对上监督学习
- 序数回归损失（尊重区间顺序）
- 校准：GRPO（组相对策略优化）用于弃权阈值

**弃权机制**:
- 不确定性阈值：如果预测置信度 < 阈值 → 弃权
- 原生弃权：内置于模型输出（非事后过滤）

### PUCT 搜索

**公式**: `PUCT(node) = Q(node) + C * sqrt(log(N_parent) / N_node)`

**组件**:
- **Q(node)**: 子树的平均加速比（利用）
- **C * sqrt(...)**: 探索奖励（访问较少的节点更高）
- **C**: 探索常数（可调，默认: 2.0）

**预算管理**:
- 固定 GPU 预算：总共 M 次评估（如 M=100-500）
- 弃权 → 消耗 1 次 GPU 评估
- 预测 → 无 GPU 成本
- 预算耗尽时搜索终止

**选择策略**:
- 贪心：始终选择最高 PUCT 分数
- 平衡利用（高 Q）和探索（低访问计数）

### 候选生成

**变异策略**:
- 算法层：更改 tiling、融合、内存访问模式
- 参数层：调整块大小、线程数、展开因子
- 模式注入：应用已知的优化模式

**多样性**:
- 拒绝重复（代码相似度 > 阈值）
- 鼓励探索多样化的优化策略

## 硬件目标

- **NVIDIA GPU**: CUDA 兼容（sm_80, sm_89, sm_90）
- **架构**: NVIDIA A100, L40S, H100
- **特性**: CUDA Compute Capability 8.0+, Tensor Cores（可选）

## 反馈信号

- **forecasted_speedup_bin**（序数）：LM 在 8 个区间中预测加速比
- **actual_speedup**（越高越好）：GPU 执行的真实加速比
- **abstain_decision**: 预测器在不确定时弃权
- **puct_score**（越高越好）：PUCT = 利用 + 探索

## 典型结果

- **加速比**: 1.5x - 4x（相对基线）
- **GPU 预算**: 100-500 次评估
- **预测器准确率**: 60-80%（序数区间）
- **弃权率**: 20-40%（取决于校准）
- **GPU 预算效率**: 最佳加速比 / GPU 评估次数（越高越好）
- **运行时间**: 30-120 分钟（取决于 GPU 预算）

## 关键参数

- **curriculum_size**: 预测器训练的初始内核数（默认: 100）
- **gpu_budget**: 固定 GPU 评估预算（默认: 200）
- **puct_c**: 探索常数（默认: 2.0）
- **abstain_threshold**: 弃权的不确定性阈值（默认: 0.3）
- **speedup_bins**: 加速比分类的序数区间（默认: [0.5, 0.7, 0.9, 1.0, 1.2, 1.5, 2.0, 3.0]）
- **tree_depth**: 最大搜索树深度（默认: 10）

## 注意事项

- **选择性代理**: 预测器在不确定时推迟到 GPU（弃权机制）
- **PUCT 搜索**: 平衡探索（不确定性）和利用（预测加速比）
- **序数区间**: 加速比被离散化为 8 个类别用于分类
- **固定 GPU 预算**: 整个搜索中 M 次评估（非每代）
- **课程训练**: 在初始数据上训练预测器，在后续搜索中应用
- **弃权率**: 预测器质量的关键指标
  - 太高 → 浪费预算（频繁 GPU 评估）
  - 太低 → 引导不佳（低置信度预测误导搜索）
- **GPU 预算效率**: 最佳加速比 / GPU 评估次数（越高越好）
- **GRPO 校准**: 调整弃权阈值以优化预算效率
